# 智能体草稿与版本管理

## 第一版使用流程

1. 在智能体详情编辑提示词、模型参数、Skills/MCP/知识库绑定、执行规则和记忆模式，并分别保存。
2. 顶部“草稿与版本”显示是否有未发布改动。点击“发布草稿”，填写说明并确认。
3. 发布生成递增版本号v1、v2等，并将新版本设为当前发布版本。
4. 展开历史版本，点击“查看 / 恢复草稿”，逐项对比版本和当前已保存草稿。
5. “用此版本恢复草稿”覆盖当前草稿配置，不改变当前发布指针。
6. “设为当前发布”只切换发布指针，不覆盖草稿。

当前工作台继续执行草稿，调用轨迹 CONTEXT_PREPARED 包含 executionSource=DRAFT。
本次只完成草稿、配置快照及发布记录管理。应用中心和按发布版本执行的业务入口尚未接入，
因此切换当前发布版本不会改变当前工作台对话的执行配置。

未保存的输入不属于草稿快照，发布前请先保存各配置项。

## 快照范围与边界

agent_version.snapshot 保存：
- 名称、描述、系统提示词。
- 模型ID和智能体参数覆盖。
- 执行规则、智能体级记忆模式。
- 有序Skills绑定、MCP服务绑定、知识库绑定。

只保存智能体配置和资源引用：
- 不复制模型供应商API Key、MCP凭证、用户会话、长期记忆或知识库文档。
- 不冻结共享模型定义/默认参数、Skills指令/文件、MCP工具定义和业务服务。
- 恢复配置不会覆盖这些共享资源；引用仍指向当前共享资源。
- 不发起模型、MCP或向量服务网络请求来发布版本。
- 切换版本不会清空任何会话或记忆。

第一版发布要求绑定可用模型；引用的Skill和MCP服务需启用，知识库需对操作者可访问。
实际MCP连通性仍应通过工具发现和调试验证。

## 数据一致性

V20 新增：
- agent_version：版本号、发布说明、配置JSONB快照、SHA-256指纹、发布者、时间。
- agent_publication：每个智能体的当前发布版本指针，复合外键限制版本必须属于该智能体。

快照通过应用接口只读，未提供编辑或删除历史版本接口。
原配置表继续保存草稿，不自动将现有智能体发布。

同一智能体的配置写入和发布通过agent_definition行锁串行化。
发布/恢复带expectedFingerprint，草稿在确认期间改变则返回409，提示刷新核对。
JSON对象字段顺序不影响指纹；数组顺序影响指纹，例如Skills执行顺序。
版本号在持有智能体锁时生成，避免并发重复编号。
恢复在单个事务中进行；引用失效、无权访问或记忆模式切换失败时整体回滚。
恢复后前端重载各配置面板，避免显示恢复前的表单值。

版本管理沿用现有智能体共享配置权限，登录用户可管理配置。
私有知识库读取权限仍独立校验，版本快照只包含知识库ID，不包含私有资料正文。

## API

前缀 /api/agents/{id}/versions：
- GET：草稿快照、指纹、当前发布版本、是否有改动、历史版本元数据。
- POST：发布，JSON {"note":"发布说明","expectedFingerprint":"64位SHA-256"}。
- GET /{version}：查看该智能体历史版本快照。
- POST /{version}/activate：切换当前发布指针。
- POST /{version}/restore：恢复草稿，JSON {"expectedFingerprint":"当前草稿指纹"}。

版本详情和变更均校验agentId与versionId所属关系，防止跨智能体操作。
写入沿用Session与CSRF保护。
