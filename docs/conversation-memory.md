# 当前会话记忆与归属

每个会话属于创建它的登录用户。后端从登录身份取得 owner_user_id，不接受前端指定归属。
会话列表、消息、发送接口、调用轨迹和工具审计均检查归属；访问他人会话返回 404。
管理员也不能读取其他用户的会话。升级前无归属的历史会话归入初始管理员账号。

原始成功及失败消息仍保存在 PostgreSQL。模型上下文使用最近最多 10 轮成功对话，
文本预算约 20,000 字符；更早的成功对话自动整理成最多 4,000 字符的结构化摘要。
摘要保存目标、已确认事实、待确认事项和编号引用，不跨会话共享，不使用向量库。
新建会话不会继承旧会话记忆。

历史超出窗口后，下一次发送会先更新摘要，再发起正常回答。
每次最多整理 20 轮，积压历史分批处理；长消息会截断摘要输入，页面显示截断和待整理提示。
摘要更新使用绑定模型，额外消耗 Token。其请求、结果、耗时和用量作为独立记忆节点展示，
总用量包括摘要与正常模型调用。供应商未返回的用量显示为未知。

摘要使用 JSON 输出模式并校验字段、长度和数量。更新失败时继续使用原摘要和近期消息，
不会因为模型返回无效摘要而中止正常回答。摘要不是精确档案；实时业务状态仍应通过工具查询。
更新采用会话执行锁和版本检查，过期请求不能覆盖摘要；幂等重放不会重复调用摘要模型。

会话详情中的“会话记忆”默认折叠。展开可查看摘要版本、覆盖轮数、更新时间和用量；
查看面板不会请求模型。第一版不提供跨会话长期记忆、用户画像、手动修改摘要或向量检索。
