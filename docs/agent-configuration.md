# 智能体配置使用说明

智能体详情现在提供：提示词与基本信息、模型、Skills、业务工具、执行规则。
每组独立保存；保存后从下一次请求生效，当前任务使用开始时读取的配置。
生成过程中界面禁止修改配置。多窗口 / API 更新不影响已经开始的运行。

## 提示词

可修改名称、描述和系统提示词。角色、职责、回答风格放在系统提示词中。
示例：你是企业客户助手，回答使用中文，客户信息必须依据工具查询结果。
保存配置不会修改模型、工具、Skills、已有会话或历史消息。
修改提示词不会清空原会话；建议使用新会话验证新的指令。

## Skills

在「Skills 管理」中创建可复用 Markdown 业务指令，包含名称、用途、指令和启用状态。
在智能体详情勾选 Skills，可调整顺序，保存后才参与运行。
每个 Skill 最多 8000 字符，每个智能体最多绑定 8 个。
已绑定 Skill 的名称与用途进入初始提示词，完整指令及 references/assets 按需加载。
支持目录导入和资源管理；暂不支持脚本执行。详见 [渐进式 Skills](progressive-skills.md)。
指令更新从所有绑定它的智能体下一次请求生效；停用后不再加入提示词。

示例：
# 客户查询规范
1. 用户未提供客户编号时，先询问编号。
2. 使用 query_customer 工具查询，不得根据名称猜测编号。
3. 仅按工具返回的数据回答，字段缺失时说明未知。
4. 工具报错时说明查询失败，不编造资料。

Skill 不授予工具权限。工具需要单独启用并绑定。
同名工具来自多个服务时，请在 Skill 中同时说明服务名称。
接口发送给模型时工具使用稳定 UUID 别名，描述中保留业务工具名与服务名。
Skills 属于模型指令，模型遵从效果需要评测；硬性权限和执行限制由后端代码控制。

## 执行规则

| 配置 | 默认 | 可配置范围 / 行为 |
| --- | --- | --- |
| 最大模型调用次数 | 6 | 1–10，包含最终生成回答的一次调用 |
| 最大工具调用次数 | 12 | 0–20，单次模型响应可能请求多个工具 |
| 总任务超时 | 170 秒 | 10–170 秒；单次模型请求仍最多 120 秒 |
| 单次工具超时 | 30 秒 | 1–30 秒，取该规则、MCP 服务超时和剩余时间的最小值 |
| 允许调用工具 | 开启 | 关闭后走普通对话，不向模型提供工具定义 |
| 工具失败策略 | 继续 | CONTINUE：错误返回模型；STOP：本轮直接失败 |

工具次数为 0 等同关闭工具；工具授权绑定仍保留。
最大模型次数为 1 时，模型可以直接回答；若提出工具请求，会因无剩余回答步骤而终止。
达到上限会保存失败状态，不会把未完成的回答当作成功，也不自动重试。
MCP 的启停设置、Schema 校验和服务限流仍然生效，Agent 规则不能绕过。
这些规则尚不包含人工审批、写操作、Token 费用预算、固定工作流和中断恢复。

## 数据与接口

V5 迁移新增 skill_definition、agent_skill_grant、agent_execution_rule。
未设置执行规则的旧智能体使用默认规则，不需要手动补数据。

- PUT /api/agents/{id}/profile：名称、描述、系统提示词
- GET / POST /api/skills：查询与创建
- PUT /api/skills/{id}：编辑、启停
- GET / PUT /api/agents/{id}/skills：查询与按顺序替换绑定
- GET / PUT /api/agents/{id}/execution-rules：读取与保存规则

核心代码：
configuration/AgentConfiguration.java：配置保存、Skill 绑定、运行时指令组装
chat/AgentChatService.java：应用配置并执行模型与工具循环
web/src/AgentSettings.tsx：智能体配置表单
web/src/SkillManager.tsx：可复用 Skills 管理

当前已接入用户登录和管理员/普通用户角色；业务数据仍为共享工作空间，尚未实现租户隔离。
